# 实验 0a — 设备微基准：fan-out 前提实测

日期：2026-09-17。设备：Colorful CN600 2TB（NVMe，DRAM-less，budget 盘），裸分区 `/home/z/hf`（无加密）。文件：8 GB 预分配，O_DIRECT，15 s/time_based。工具：fio 3.36，libaio。

**注意：这是开发机（Broadwell i7-6850K，12 线程），不是"modern hardware"目标。相对结构（QD 缩放曲线、bs-延迟曲线）可迁移；绝对值不可外推。**

## 场景换算（修正脚本换算 bug 后）

| 场景 | 成本 |
|---|---|
| fan-out=20，串行 4K（依赖链） | **1.89 ms** |
| fan-out=20，批量 QD32 | **≈ 0.21 ms**（9.3×） |
| fan-out=20，每文档一页 64K，串行 | 3.75 ms |
| 整个 8 MB tile 一次顺序读 | **9.99 ms** |
| 单页 64K QD1（点读） | 0.19 ms |
| 单页 16K QD1（点读） | 0.11 ms |

## 结论

1. **批量并行 = 9.3×**：独立扇出必须并发下发（QD≥32），串行依赖链是最差形状。
2. **"塌缩成整瓦片读"在本设备被证伪**：8 MB 顺序读（10 ms）比 20 个串行 4K（1.9 ms）贵 5 倍。正确形状 = **页粒度 + 反向索引 + 批量并发**——与 `docs/engine.md` 的设计一致，该设计经受住了实测。
3. **页大小默认应下调至 16 KB**（点读延迟仅比 4K 差 12%，目录条目少 4 倍）；64K 在此带宽下点读成本翻倍。页大小保持 autotunable：旗舰盘（带宽↑更快）会收窄大页劣势。
4. **设备尾延迟 p99 ≈ 10× 均值**（QD1 979 µs）：SLO 分析必须用 percentile；`objective.md` 的锚定曲线须计入设备尾。
5. 成本模型常量（本设备）：依赖点读 ≈ 94–106 µs（4–16K）；批量摊薄 ≈ 10.3 µs/读（QD32 4K）；带宽上限 ≈ 820 MiB/s。
